# 温泉剧本机制文档（onsen / scenarioId = 12）

> [术语表](glossary.md)（术语与口径分歧的单一事实源）配套：**表格与术语以术语表为准，
> 本文只补公式、流程与实现落点**。实现入口均在 `src/` 下，逐节标注。

## 1. 回合与阶段

- 0 基回合 `turn ∈ [0,77]`（78 回合）；阶段机为剧本私有枚举 `Stage`（`src/game/stage.rs`），
  顺序 `Begin → Distribute → Bathing → Train → AfterTrain`，对外投影 `StageId 0..4`
  （显式赋号，改号＝旧种子与基线失效）。
- 决策点只有 `Bathing`（用券 / 不用券）与 `Train`（训练 / 比赛 / 休息 / 出行 / 治病 / PR）；
  源泉选择与装备升级寄生于 `Begin` 的 `pending_selection` 流程（`src/game/dig.rs`）。
- 合宿（`turn ∈ [36,40) ∪ [60,64)`）：不挖掘、不出门、不 PR、不治病，训练等级固定 5；
  决赛期（`turn ≥ 72`）：73 / 75 / 77 强制比赛。
- 新回合边界重派三条随机轴（见 §9）。

## 2. 源泉与温泉效果

- 源泉一览、解锁回合、地层需求量见术语表 §3（索引 0 基＝数据 id − 1）。
- **锁面板**：`onsen_buff` 是「已挖源泉效果之和」，仅用券（或面板为空）时重算
  （`update_scenario_buff(use_ticket)`，`src/game/dig.rs`）——已挖出的新源泉效果要
  **用券**才进面板；旅馆档与挖掘力则每回合重算。
- 效果生效期间 `buff_remain_turn = 2`（覆盖当回合与下回合训练阶段），结束后清零；
  生涯比赛加成（`career_race_bonus`）只在生效期间计入比赛倍率（见 §6）。

## 3. 地层与挖掘（`src/game/dig.rs`）

- 挖掘力（每地层独立）＝ ①蓝因子档 `dig_blue_bonus`（每 3 点蓝因子算 1 个）＋
  ②属性档位 `dig_stat_bonus`（按五维落在 `dig_stat_ranks` 哪一档）＋ ③装备 `dig_tool_level[dig_level]`。
- 挖掘量：`floor(基础值 × (100+挖掘力)/100)`；基础值按动作：
  训练 25+人头数（排除理事长 / 记者）/ 目标赛 25 / 其他赛 15 / 休息 · 普通出行 15 /
  友人出行 25 / PR 11 / 治病 0。
- **跨地层公式不对称**（旧实现口径，勿对称化）：当前层挖掘力**含**剧本链接加成（命中
  `link_effect` 的角色 / 支援卡该地层 +10%）；挖掘量超过当前层剩余量时当前层取剩余量
  **整数**（不 floor），余量按**下一层挖掘力（不含链接）**折算并受下一层剩余量封顶。
- 挖掘进度**只增不减**：每满 30 点触发一次 `dig_bonus`（`[速耐力根智 体力]`）；
  挖掘奖励的体力变化同样并入超回复累计与判定。
- 挖通一座源泉：发温泉券（量按友人卡稀有度，见术语表 §7.3）并挂起「选源泉 + 升装备」；
  索引 0 的基础温泉开局即视为已挖通（剩余量 0，不重复发券）。
- 装备等级 1–6，加成 0/30/50/70/100/130；升级后挖掘力立即重算。

## 4. 入浴与超回复（`src/game/bath.rs`）

用券流程（`do_use_ticket`）：

1. 刷新温泉效果面板（解锁锁面板）；
2. 羁绊最低的 N 人各 `+friendship`（满 100 不再加；N 与数值来自面板）；
3. 体力恢复：超回复封顶取**临时上限** `super_effect.temp_max_vital = 150`（不写回
   `max_vital`）；非超回复封顶取常规上限；
4. 干劲 `+motivation`（封顶 5）；
5. 超回复额外效果：技能点 `+super_effect.pt`、红点 `hotel.hint + 2` 次（口径见术语表 §13.2 #3）；
6. 扣 1 张券，效果持续 2 回合；秘汤分身（见 §8）与红点发生率提升重判。

超回复分档（`calc_super_prob`）：按累计挖掘消耗体力（`dig_vital_cost`）每 50 点一档查
`super_probs`；累计 ≥275 保底必发。判定先于累计（概率按「已有 + 本次」查档），
触发即清零累计；传说秘泉挖通后超回复就绪状态可再次触发。

**超上限体力语义（术语表 §13.2 #11，独立于引擎实现）**：
`OnsenGame::with_vital_overflow`（`src/game/mod.rs`）在体力入账点包裹引擎
`Uma::add_value`——

- 正向回体：体力已不低于上限时**只失效**（不把体力压回上限）；
- 负向消耗：照常从当前值扣减，下限 0（不压回上限）；
- 事件 `max_vital` 增量照常加到真实上限；
- 临时上限是数据常量，与真实 `max_vital` 互不影响。

已覆盖的入账点：训练 / PR / 事件 / 休息心得 / 挖掘奖励 / 休息 / 治病 / 非超回复入浴。

## 5. 训练（`src/game/train.rs`、`src/game/traits.rs`）

- 训练基础值表 `training_basic_value`（`[训练 0-4][等级 0-4]`）由剧本数据自持
  （`TrainingValueSource::training_basic_table`）。
- **上下两层分开算、各自逐槽截 100**（`calc_training_value` 覆写）：
  下层＝卡片 buffs 的引擎默认值截 100；上层＝温泉效果并入 buffs 后重算总值的差值截 100；
  卡片无友情加成时温泉友情也不生效（旧实现口径）。
- **失败率下降补实现**（术语表 §13.2 #1）：`do_train` 把「卡片 buffs + 温泉效果生效期间的
  `fail_rate_drop`」合并后交引擎失败率公式，引擎公式不动；失败再判定一次仍失败为大失败
  （生病 + 不擅长训练）。
- 训练后通用处理（羁绊 / 红点 / 加练 / 友人点击）走引擎可复用件
  `BaseGame::default_after_train`（H2 钩子）。
- 成功才挖掘；失败 / 大失败按事件链结算且不入挖掘。
- 得意率：`deyilv` ＝ 卡片累计效果 + 当前旅馆档加成（见 §8）。
- 训练等级：每 4 次同训练 +1 级（封顶 5）；下合宿固定 5。

## 6. 比赛与倍率（`src/game/action.rs`）

经引擎 H1 钩子 `BaseGame::push_race_event(scale, pt_rate)` 构造比赛事件：

- 生涯赛（`turn < 72`）：`scale = (100+race_bonus)/100 × 剧本倍率 × 源泉加成`；
  源泉加成（`career_race_bonus`）只在温泉效果生效期间计入；
- 决赛期（`turn ≥ 72`）：不再乘剧本倍率；
- 自选比赛：只吃引擎赛后加成（`race_bonus`），不吃剧本倍率与源泉加成；
- 特殊角色 1063（生野狄杜斯）：出道赛后（turn > 12）生涯赛属性再 ×2.7、PT ×0.45
  （保留旧实现口径，术语表 §13.2 #7）。

比赛统一挖掘并记 `set_race`；目标赛挖掘基础值 25、自选赛 15。

## 7. 事件体系（`src/game/event.rs`）

- 三层来源：①引擎 `events.story_events`（通用固定回合）；②本仓 `scenario_events`
  （温泉杯 5 条固定事件，见术语表 §7.1）；③无固定事件时按引擎事件分布抽随机事件
  （支援卡连续 / 马娘 / 掉心情），禁事件回合不抽。
- 友人出门：未解锁时按羁绊 60 分界取解锁概率，命中后本回合只发生这一件。
- 女将（保科健子）事件链与出行 5 段券规则见术语表 §7.2 / §7.3；女将解锁出行时获得
  休息心得。
- 事件结算：先走引擎 `BaseGame::apply_event`（数值入账 / 计数 / 友人加成），再补温泉特例
  （继承 / 切者 / 女将解锁 / 出行券 / 年末训练等级 +1 / 宴会再发券）；体力消耗（负数）
  按计算值并入超回复分档；事件羁绊按人头身份回账（卡组下标 ≠ 人头下标）。
- 年末事件（汤浴会）只实现大成功档（数据里的单选项事件）。

## 8. 旅馆档、PR、休息心得、分身

- **旅馆档**：按已挖源泉数取最高满足档（3/5/6/7 座），给得意率 +40/70/100/120 与
  超回复红点 +1/+1/+1/+2（`OnsenData::hotel_rank`）。
- **PR 活动**：体力 −15、五维 +6、技能点 +15、温泉券 +1（数值取 `pr_base_value`），
  无次数上限；体力消耗并入超回复判定；挖掘基础值 11（按 1 个客人计）。
- **休息心得**：女将解锁出行时获得；每回合开始体力 +5（超上限时只失效），持续回合按
  引擎概率表推进或结束。
- **秘汤分身**：温泉效果生效且 `split > 0` 且支援卡种类（全部 7 类卡种，含友人 / 团队）
  非零类数 ≥5 时，把已在训练中的人头再追加分配 `split` 人（每张卡最多分身一次）。

## 9. 三轴随机与派生

- 局面流（`TurnFixedRng`）与事件流（`EventRng`）从 `BaseGame` 取；策略流（`StrategyRng`）
  剧本自持，每回合按 `(master, turn)` 派生（`reset_strategy_stream`）——动作结算与剧本机制
  随机走策略流，规则流（`turn_fixed` / `event`）与决策流分离，CRN 配对依赖这一点。
- 主种子注入点：`Game::set_rule_master`（引擎两轴 + 剧本策略轴一起重置）；未注入就推进
  即报错。
- 决策流只喂 `Trainer`（`run_stage` 的 `decision: &mut StdRng`）。

## 10. 装配与呈现（A8）

- `build_game(cfg, data)`：从引擎配置 + 剧本数据装配一局（`src/game/mod.rs`）；引擎数据根、
  剧本数据根、剧本配置根全部由宿主注入，本仓不写死路径。
- 剧本配置段 `config/onsen_config.toml`（`src/config.rs`）：复用引擎 H5 钩子语义
  （`OverlayConfig` + `parse_with_overlay`）——默认层字段齐全、未知键严格报错；覆盖层
  与默认层同名 `onsen_config.toml`、放宿主工作目录、存在才合并；当前含
  `[onsen_order]` 源泉选择优先顺序（按年，索引 0 基）。
- `OnsenView`（`src/game/mod.rs`）：剧本资源快照的**单一取数口**（形态 A）：券与入浴、
  源泉与挖掘（状态 / 剩余 / 进度 / 挖掘力 / 装备）、旅馆档、效果面板；快照语义、
  `non_exhaustive`、不进契约 trait。
- bin（`src/main.rs`）：`cargo run --release -- [引擎数据根 [剧本数据根 [剧本配置根 [训练员]]]]`，
  训练员缺省 `onsen`（手写策略），可切 `random`（引擎随机基线）。
- 仓根 `ai_config.toml`（宿主覆盖层）：温泉只支持女将友人卡（非保科友人卡建局即报错，
  见 glossary §13.2 #13），覆盖层把引擎默认卡组的塔可换成女将（302764）；其余字段沿用
  数据根默认层。

## 11. 手写策略（B5，`src/trainer.rs`）

移植旧仓 `HandwrittenEvaluator` / `HandwrittenTrainer`：

- **守门链**（按序短路）：①有病 → 治病；②生涯赛回合 → 比赛；③入浴决策（超回复就绪 /
  券 ≥2 / 体力 <55 / 已挖秘汤 → 用券）；④挖掘选择 → 年份顺序表（`onsen_config.toml`），
  装备升级 → 推荐表 `RECOMMENDED_TOOL_TYPE`（按当前源泉取）。
- **打分表**：训练（属性收益 + 上限软约束 + 体力分段 + 失败期望混合 + 彩圈 + 人头羁绊 /
  红点 + 效果期 ×1.15 + 挖掘价值 + 类型偏好）、休息 / 普通出行（体力段 + 干劲补）、
  友人出行（基础 + 回合修正 + 超回复调整）、比赛（生涯倍率 / 自选窗口折算）、
  PR（第一年累计消耗 ×1.2 + 无券补分）；一屏超参常量集中在文件头部。
- **秘汤豁免**：挖通秘汤汤驹（索引 8）后跳过体力评估惩罚，休息 / 出行降为负基础分。
- 与旧仓的两处取舍：事件选项沿用本仓 A7 贪心（旧仓恒取首项）；打分兜底取首项
  （旧仓随机兜底为不可达分支）。生涯赛打分直接读锁面板（旧仓口径），实际结算仍按
  效果生效期判定。

## 12. 与旧仓统计口径对照

预期内差异（详见 [M1 方案 §7](plan/m1_plan.md) 与术语表 §13）：

| # | 差异 | 对照时注意 |
|---|---|---|
| 1 | 随机流按引擎三轴重排（旧温泉是唯一未改造剧本） | 同种子数值整体位移；**只比统计量（多局均值 / 分布），不比逐位** |
| 2 | 基础温泉「失败率下降 20」补实现（旧仓未生效） | 失败率整体下降，长局数值上移 |
| 3 | 训练后羁绊按引擎修正口径（支援卡 +7 / 理事长 · 记者 +5 / 爱娇 +2）；旧温泉 +7 / +2 | 羁绊与闪彩节奏略变 |
| 4 | 汤浴会只实现大成功档 | 不出现「ふつう」档 |
| 5 | 手写策略打分与旧仓逐值一致（超参同值），但事件选项为贪心而非恒取首项 | 策略分布整体接近但不重合 |
| 6 | 非保科友人卡**建局报错**（旧仓降级为 `OtherFriend` 继续跑） | 带非女将友人卡的卡组直接被拒；标准女将卡组无影响（glossary §13.2 #13） |

比对方法：固定种子基线见 `baselines/`（`UMAAI_ONSEN_UPDATE_BASELINE=1` 重写，
默认逐字段比对、位移即失败）；跨仓统计对照用各自批量模拟出口（旧仓
`crates/umasim`、本仓 bin 批量跑多局）后比评分 / 五维 / 挖掘数分布。
